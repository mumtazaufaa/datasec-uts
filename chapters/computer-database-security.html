Intinya dalam 30 detikKeamanan data punya 5 tujuan: Confidentiality (rahasia), Integrity (utuh), Availability (tersedia), Authenticity (asli), Accountability (bisa dilacak). Ada serangan (attack), ada layanan (service) dan alat (mechanism) untuk melawannya. Semua istilah dijelaskan di bawah, pelan-pelan.

A. Apa itu keamanan komputer?

Cybersecurity = melindungi informasi yang disimpan, dikirim, dan diproses di jaringan komputer, perangkat digital, dan internet. Caranya bisa lewat aturan organisasi (kebijakan dan prosedur) dan lewat teknik (enkripsi dan protokol komunikasi yang aman).

IstilahArtinya (versi gampang)
Information securityMenjaga informasinya supaya tetap rahasia, utuh, dan tersedia (CIA). Bisa ditambah sifat lain: asli, bisa dilacak, tidak bisa disangkal, dan dapat diandalkan.
Network securityMenjaga jaringan dan layanannya dari perubahan, perusakan, atau kebocoran tanpa izin, dan memastikan jaringan bekerja benar tanpa efek samping berbahaya.
Cara ingatInformation security = menjaga isinya (datanya). Network security = menjaga jalannya (jaringannya). Keduanya bagian dari cybersecurity.

B. Tujuan keamanan: CIA Triad + 2 tambahan

CIA di sini bukan badan intelijen Amerika. CIA adalah singkatan dari tiga tujuan utama keamanan: Confidentiality, Integrity, Availability. Disebut triad karena ada tiga. Lalu slide dosen menambah dua lagi: Authenticity dan Accountability. Jadi totalnya 5 tujuan.

C. OSI Security Architecture: Serangan, Layanan, Alat

Ini kerangka untuk memikirkan keamanan lewat tiga hal:

IstilahArtinyaAnalogi rumah
Security attack (serangan)tindakan yang membahayakan keamananmaling mencoba masuk
Security service (layanan)apa yang dilindungi/dijamin"rumah harus aman dari maling"
Security mechanism (alat)cara/teknik untuk menjalankan layanankunci, gembok, alarm
Cara ingatAttack = ancaman. Service = tujuan. Mechanism = alat. Alat dipakai supaya layanan tercapai dan serangan gagal.

1. Security attacks (serangan)

JenisSeranganArtinya (gampang)
Passive (cuma mengintip, data tidak diubah, sulit ketahuan)Release of message contentsisi pesan (telepon, email, file) dibaca orang yang tidak berhak
Traffic analysisisi pesan sudah disamarkan (dienkripsi), tapi penyerang melihat pola: siapa kirim ke siapa, seberapa sering. Seperti melihat banyak surat keluar-masuk walau tidak bisa membacanya.
Active (mengubah data atau membuat data palsu)Masqueradesatu pihak menyamar jadi pihak lain
Replaymenangkap data lalu mengirim ulang untuk efek tidak sah (contoh: merekam perintah "transfer" lalu mengirimnya lagi)
Modification of messagesmengubah isi pesan. Contoh: man-in-the-middle, penyerang di tengah mengubah data antara client dan server
Denial of service (DoS)membuat layanan tidak bisa dipakai (dibanjiri permintaan)
Cara hafalPasif = Intip (2: baca isi, analisis lalu lintas). Aktif = M-R-M-D: Menyamar, Replay (kirim ulang), Mengubah pesan, DoS (bikin down). Pasif lebih sulit ketahuan, jadi fokusnya mencegah; aktif fokusnya mendeteksi dan memulihkan.

D. Attack surface dan attack tree

Attack surface = semua titik lemah yang bisa dijangkau dan dimanfaatkan penyerang. Bayangkan pintu dan jendela rumah: makin banyak, makin banyak jalan masuk. Kalau permukaan diperkecil, tugas penyerang makin sulit. Contoh dari slide: port terbuka di server web, layanan di dalam firewall, kode yang memproses email/XML/dokumen, antarmuka SQL dan form web, serta karyawan yang bisa kena social engineering.

JenisTitik lemahnya di manaContoh
Networkjaringan perusahaan, WAN, internet (fokus: software web server)port terbuka
Softwarekode aplikasi, utilitas, sistem operasibug di form web
Humanmanusia: social engineering, salah manusia, orang dalam yang dipercayakaryawan tertipu email palsu
HafalAttack surface ada 3: Network, Software, Human ("NSH").

Attack tree = diagram pohon yang menggambarkan cara-cara mencapai satu tujuan serangan. Tujuan serangan ada di akar (paling atas). Cabangnya adalah langkah-langkah (sub-tujuan), dan tiap sub-tujuan bisa punya cabang lagi.

NodeArtinyaContoh
ANDsemua anaknya harus tercapaimencuri uang di brankas: harus dapat kunci DAN masuk ruangan
ORsalah satu anaknya cukupmasuk ruangan: lewat pintu ATAU jendela

Cabang bisa diberi nilai (tingkat kesulitan, biaya) supaya serangan bisa dibandingkan. Gunanya: membantu mendesain sistem dan memilih countermeasure.

E. Model keamanan jaringan

Keamanan dibutuhkan ketika data yang dikirim perlu dilindungi dari lawan (opponent). Semua teknik keamanan punya 2 komponen:

  1. Transformasi pada informasi yang dikirim. Contoh: enkripsi (membuat pesan acak sehingga tak terbaca lawan) atau menambah kode dari isi pesan untuk memverifikasi pengirim.
  2. Informasi rahasia yang dipakai bersama oleh dua pihak dan tidak diketahui lawan. Contoh: kunci enkripsi.

Ada 4 tugas untuk merancang layanan keamanan:

#Tugas
1Merancang algoritma untuk transformasi keamanan (lawan tidak boleh bisa mengalahkannya).
2Membuat informasi rahasia (kunci) untuk algoritma itu.
3Membuat cara mendistribusikan dan berbagi informasi rahasia.
4Menentukan protokol yang dipakai dua pihak, memakai algoritma dan informasi rahasia itu.
HafalAlgoritma → Kunci → Bagikan kunci → Protokol ("A-K-B-P").

G. Database security (Session 2)

1. Database dan DBMS

  • Database = kumpulan data terstruktur beserta hubungan antar data. Bisa berisi data sensitif, jadi perlu dilindungi.
  • DBMS = program untuk membuat dan mengelola database serta menjawab query. Isinya antara lain tabel deskripsi database, authorization table (mengecek izin user), dan concurrent access table (mencegah bentrok kalau banyak yang mengakses bersamaan).
  • DDL mendefinisikan struktur data. DML dipakai untuk mengolah data.

2. Database relasional dan SQL

IstilahArtinya (gampang)
Relation / tabletabel baris × kolom
Tuple / rowsatu baris (satu data)
Attribute / columnsatu kolom (satu jenis data)
Primary keykolom dengan nilai unik, penanda satu baris (seperti NIM)
Foreign keykolom yang menunjuk primary key tabel lain, nilainya boleh berulang
Viewtabel virtual berisi hasil query. Sering dipakai untuk membatasi apa yang boleh dilihat user

SQL = bahasa standar untuk mendefinisikan, mengolah, dan meng-query data relasional. Perintah untuk mengambil data: SELECT.

3. SQL Injection (SQLi)

Salah satu serangan jaringan yang paling umum dan berbahaya. Penyerang menyisipkan perintah SQL lewat kolom input. Akibatnya: data diubah atau dihapus, menjalankan perintah OS, atau serangan DoS. Triknya: menutup teks lebih awal, lalu menambah perintah sendiri.

Contoh dari slideQuery asli: SELECT fname FROM student WHERE fname = '[input user]';
Input penyerang: John'; DROP table Course;--
Hasilnya: teks ditutup setelah John, perintah DROP table Course ikut jalan, dan -- membuat sisa query jadi komentar.

Contoh lain (tautology): SELECT info FROM user WHERE name='$name' AND pwd='$pwd'. Penyerang isi name dengan ' OR 1=1 --. Kondisi 1=1 selalu benar, jadi login lolos tanpa password.
KategoriJenisCiri
In-band (hasil diterima lewat jalur yang sama)Tautologykondisi dibuat selalu benar
End-of-line commentsisa query dibuat jadi komentar
Piggybacked queriesmenempel query tambahan di belakang query sah
InferentialIllegal / logically incorrect querytidak ada data dikirim langsung; penyerang menyimpulkan struktur database dari perilaku server
Out-of-band-dipakai kalau pengambilan data dibatasi tetapi koneksi keluar dari server longgar
Cara melawan SQLi (3 cara)Defensive coding (validasi input lebih ketat), Detection (signature based, anomaly based, code analysis), Runtime prevention (cek query saat dijalankan: sesuai pola yang diharapkan atau tidak).

4. Kontrol akses database

DBMS menganggap user sudah login, lalu memberi hak akses (create, insert, delete, update, read, write) pada seluruh database, tabel, atau baris/kolom tertentu. Siapa yang mengatur hak itu:

KebijakanArtinya
Centralizedhanya beberapa user istimewa yang boleh memberi/mencabut hak
Ownership-basedpemilik tabel yang memberi/mencabut hak
Decentralizedpemilik boleh memberi hak untuk memberi hak ke orang lain
Perintah SQL untuk hak aksesGRANT SELECT ON ANY TABLE TO john = beri hak baca.
REVOKE SELECT ON ANY TABLE FROM john = cabut hak baca.
Hak umum: SELECT, INSERT, UPDATE, DELETE, REFERENCES. WITH GRANT OPTION = penerima boleh meneruskan hak itu. PUBLIC = semua user.

Cascading authorization: hak yang diteruskan itu menyebar seperti rantai, dan kalau dicabut, ikut tercabut ke bawah. Contoh gambar: kalau Bob mencabut hak David, hak turunan yang hanya berasal dari Bob ikut hilang.

5. RBAC di database

RBAC (role-based access control) = hak akses diberikan ke peran (role), lalu user ditempatkan pada peran. Cocok untuk database karena satu database melayani banyak aplikasi. Ada 3 jenis user: application owner (pemilik objek, boleh memberi role ke end user), end user (memakai lewat aplikasi, tidak memiliki), dan administrator (mengelola sebagian atau seluruh database). RBAC harus bisa membuat/menghapus role, menentukan izin role, dan menetapkan/mencabut user dari role.

6. Inference

Inference = user memakai query yang diizinkan, lalu menyimpulkan informasi yang tidak diizinkan. Jalur untuk itu disebut inference channel. Masalahnya: gabungan beberapa data tak sensitif bisa jadi sensitif.

Dua cara mencegahnya: ubah desain database/kontrol akses (mis. pecah tabel), atau awasi query dan tolak/ubah kalau terdeteksi inference channel.

Untuk statistical database (hanya boleh melihat statistik):

PendekatanArtinya
Query restrictionquery yang berisiko ditolak, jawaban yang diberi tetap akurat. Contoh: query size restriction, query hanya boleh jika jumlah record hasilnya antara k dan N − k (N = jumlah record).
Perturbationsemua query dijawab, tetapi jawabannya diperkirakan (ditambah noise). Kelemahan: akurasi turun dan bisa bias.

7. Enkripsi database

Database dilindungi berlapis: firewall, autentikasi, kontrol akses OS, kontrol akses DBMS, lalu enkripsi. Enkripsi bisa di tingkat: seluruh database (tidak fleksibel), field (sederhana tapi kurang fleksibel), atau record (baris) / kolom (paling baik, memakai attribute index supaya pencarian cepat, walau indeks bisa membocorkan urutan perkiraan).

4 pihak: data owner (pemilik data), user (pengirim query), client (front-end yang mengubah query user menjadi query atas data terenkripsi), dan server (menyimpan data terenkripsi, tanpa kunci). Alur: (1) user kirim query → (2) client mengenkripsi lalu kirim ke server → (3) server memproses dan mengirim hasil terenkripsi → (4) client mendekripsi dan menampilkan ke user.
